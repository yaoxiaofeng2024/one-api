## 2.2 添加 AI 渠道

渠道是 One-API 的核心概念，每个渠道对应一个 AI 供应商的 API Key。

### 添加 OpenAI 渠道

1. 进入 **渠道管理** 页面
2. 点击 **"添加渠道"**
3. 填写配置：

| 字段 | 填写内容 | 说明 |
|------|----------|------|
| 类型 | OpenAI | 选择渠道类型 |
| 名称 | OpenAI 主账号 | 自定义名称 |
| Base URL | 留空（或填代理地址） | 默认使用官方地址 |
| 密钥 | `sk-xxxxxxxxxx` | 填入你的 OpenAI API Key |
| 模型 | 点击"填入模板"或手动选择 | 选择该 Key 支持的模型 |
| 分组 | default | 用户组映射 |

4. 点击 **"提交"** 保存

### 添加其他渠道示例

**添加 Claude 渠道：**
- 类型选择：Anthropic Claude
- 密钥填入 Claude API Key
- 模型选择：claude-3-sonnet、claude-3-opus 等

**添加国内渠道（以 DeepSeek 为例）：**
- 类型选择：DeepSeek
- 密钥填入 DeepSeek API Key
- 模型选择：deepseek-chat、deepseek-coder 等

### 渠道高级配置

| 配置项 | 说明 | 推荐值 |
|--------|------|--------|
| 优先级 | 数字越大越优先使用 | 主渠道设 10，备用渠道设 1 |
| 权重 | 负载均衡权重 | 同优先级渠道按权重分配 |
| 自动禁用 | 渠道报错时自动禁用 | 开启（默认） |
| 测试模型 | 用于测试渠道是否可用 | 选最便宜的模型 |

### 测试渠道

添加渠道后，点击渠道列表中的 **"测试"** 按钮，验证渠道是否可用：

- ✅ 测试通过 → 渠道状态正常
- ❌ 测试失败 → 检查 API Key、Base URL、网络连通性

## 2.3 管理令牌（API Key）

令牌（Token）是用户调用 AI 接口的凭证。每个用户可以创建多个令牌，用于不同场景。

### 创建令牌

1. 进入 **令牌管理** 页面
2. 点击 **"添加令牌"**
3. 填写配置：

| 字段 | 说明 | 示例 |
|------|------|------|
| 名称 | 令牌标识 | "我的开发环境" |
| 额度 | 令牌可用额度（-1 为无限） | 1000000 |
| 过期时间 | 令牌有效期（-1 为永不过期） | 2026-12-31 |
| 允许的模型 | 限制令牌可调用的模型 | 留空=全部允许 |
| 允许的 IP | 限制调用来源 IP | 留空=全部允许 |

4. 提交后会生成一个 `sk-xxxx` 格式的令牌，**请妥善保存**，关闭后无法再次查看完整令牌！

### 令牌额度说明

One-API 的额度单位：**1 美元 = 500000 额度**

- 用户总额度：管理员在用户管理中分配
- 令牌额度：从用户额度中分配给单个令牌
- 每次调用消耗的额度根据模型定价自动计算

## 2.4 调用 AI 接口

One-API 兼容 OpenAI API 格式，你可以用任何支持 OpenAI 的客户端来调用。

### 使用 cURL 测试

```bash
curl http://localhost:3000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-你的令牌" \
  -d '{
    "model": "gpt-3.5-turbo",
    "messages": [
      {"role": "user", "content": "你好，请介绍一下你自己"}
    ],
    "stream": false
  }'
```

### 使用 Python OpenAI SDK

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的令牌",
    base_url="http://localhost:3000/v1"
)

response = client.chat.completions.create(
    model="gpt-3.5-turbo",
    messages=[
        {"role": "user", "content": "你好，请介绍一下你自己"}
    ]
)

print(response.choices[0].message.content)
```

### 流式调用

```python
stream = client.chat.completions.create(
    model="gpt-3.5-turbo",
    messages=[
        {"role": "user", "content": "写一首关于春天的诗"}
    ],
    stream=True
)

for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")
```

### 支持的 API 端点

| 端点 | 方法 | 功能 |
|------|------|------|
| `/v1/chat/completions` | POST | 聊天补全 |
| `/v1/completions` | POST | 文本补全 |
| `/v1/images/generations` | POST | 图片生成 |
| `/v1/audio/speech` | POST | 语音合成 |
| `/v1/audio/transcriptions` | POST | 语音转文字 |
| `/v1/models` | GET | 模型列表 |

> **关键：** 无论后端实际调用的是 OpenAI、Claude 还是其他厂商，对外接口格式始终统一为 OpenAI 格式，这就是 One-API 的核心价值。

## 2.5 用户与权限管理

### 角色体系

| 角色 | 值 | 权限范围 |
|------|-----|----------|
| Guest | 0 | 未登录访客，仅可注册/登录 |
| User | 1 | 普通用户，可创建令牌、调用接口 |
| Admin | 10 | 管理员，可管理用户、渠道、日志 |
| Root | 100 | 超级管理员，可管理所有系统配置 |

### 用户管理操作

1. **创建用户**：用户管理 → 添加用户 → 设置用户名、密码、初始额度
2. **分配额度**：用户列表 → 编辑 → 修改额度
3. **禁用用户**：用户列表 → 禁用（用户无法登录和调用）
4. **删除用户**：用户列表 → 删除（不可恢复）

### 兑换码

兑换码用于批量给用户充值额度：

1. 进入 **兑换码** 页面
2. 点击 **"添加兑换码"**
3. 设置名称和额度
4. 选择生成数量（可批量生成）
5. 将生成的兑换码分发给用户
6. 用户在"个人信息"页面输入兑换码充值

## 2.6 日志与统计

### 查看调用日志

进入 **日志查询** 页面，可以查看：

- 每次调用的模型、Token 消耗、额度消耗
- 调用时间、来源 IP
- 使用的渠道、是否重试
- 流式/非流式

### 仪表盘统计

仪表盘展示：

- 总请求数、今日请求数
- 总消耗额度、今日消耗额度
- 活跃用户数
- 各模型使用占比

### 用 MySQL 直接查询统计

```sql
-- 今日各模型消耗
SELECT model_name, COUNT(*) as count, SUM(quota) as total_quota
FROM logs
WHERE timestamp >= UNIX_TIMESTAMP(CURDATE())
GROUP BY model_name
ORDER BY total_quota DESC;

-- 某用户本月消耗
SELECT SUM(quota) as monthly_quota
FROM logs
WHERE user_id = 1
AND timestamp >= UNIX_TIMESTAMP(DATE_SUB(CURDATE(), INTERVAL DAY(CURDATE())-1 DAY));
```
